---
title: SuperUser and first login
description: Sign in with Starling's first-run administrator account.
---

Starling creates the built-in SuperUser account on first start and prints a generated password. Save it in a password manager. In the distributed Docker stack, inspect `docker compose logs userdata`; in the all-in-one service, use `docker compose logs starling`. The password is only printed when it is created; it does not appear on every restart.

Open Fancy Mumble, connect to your server, enter SuperUser as the username, and use the generated password when prompted. The SuperUser bypasses channel ACLs and can bootstrap channels, accounts, and server settings.

If you lose the password, stop the server and run the command against the same data directory or service configuration as the running server:

~~~sh
starling set-superuser-password "a-new-strong-password" --server 1 --config starling.toml
~~~

Omit the server argument for the first configured instance. The older Docker variable MUMBLE_SUPERUSER_PASSWORD and the C++ mumble-server --set-su-pw command do not configure Starling.

After logging in, set a welcome text, create channels, configure ACLs and roles, and make a [backup](/server/upgrade/).
